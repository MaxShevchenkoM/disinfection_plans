# План клініки

Інтерактивний план приміщень із зонами, потоками, ризиками і процедурами дезінфекції. Дані зберігаються в Supabase.

| Середовище | Гілка | Адреса | Таблиця |
|---|---|---|---|
| Прод | `main` | `/` | `plan_prod` |
| Препрод | `preprod` | `/preprod/` | `plan_preprod` |

## Будова коду

Без збирання й залежностей: браузер завантажує файли по черзі, як вони перелічені в `index.html`.
Кожен файл починається з короткого опису, кожна функція — з коментаря.

| Файл | Що в ньому |
|---|---|
| `index.html` | Розмітка: верхня панель, стрічка, полотно, бічна панель |
| `css/app.css` | Усі стилі, зокрема мобільний вигляд (`body.mob`) |
| `js/01-data.js` | Довідкові дані: шари, види об'єктів, каталог, матеріали, значки |
| `js/02-state.js` | Стан застосунку і спільні помічники |
| `js/03-geometry.js` | Координати, відстані, перетини, зони і їхні типи |
| `js/04-render.js` | Малювання плану (`draw`, `drawSoon`) |
| `js/05-analysis.js` | Конфлікти потоків, ризики, вимоги і процедури зони (з кешем) |
| `js/06-panels.js` | Панель властивостей, дерево об'єктів, вкладки |
| `js/07-passport.js` | Паспорт зони, меню типу зони, «Результат» |
| `js/08-catalog.js` | Каталог «Додати», нещодавні, пошук |
| `js/09-editor.js` | Миша і клавіатура: виділення, перетягування, стіни, рух, файли |
| `js/10-menus.js` | Контекстне меню, плаваюча панель, буфер, масштаб, довідка |
| `js/11-mobile.js` | Мобільний вигляд і дотик |
| `js/12-db.js` | Supabase: довідники, клініки, збереження, вхід |
| `js/13-disinfectants.js` | Імпорт таблиці дезінфектантів і ціни |
| `js/14-dialogs.js` | Закриття вікон |
| `js/15-init.js` | Запуск — останнім |

Важливо: усі файли ділять спільні імена. Код, що виконується одразу під час завантаження
(а не в обробниках подій), може звертатися лише до того, що оголошено у файлах вище за списком;
виклики, яким потрібне все, — у `15-init.js`.

Форматування — Prettier (`.prettierrc.json`).

## Як вносити зміни
1. Зміни — лише в гілку `preprod`.
2. Перевірка: `python3 tests/run.py` (Playwright + Google Chrome). Тест збирає сторінку із заглушкою
   замість бази (`tests/stub.js`, дані — `tests/kb.json`) і проходить основні дії на комп'ютері й телефоні.
3. `./deploy.sh` публікує обидві гілки в `gh-pages`; препрод з'являється на `/preprod/` з тестовими даними.
4. Перевірили — зливаєте `preprod` у `main` і знову `./deploy.sh`.
5. Дані проду ніколи не змінюються препродом. На препроді є кнопка «З проду в препрод».

## Доступ
- Переглядати може кожен із посиланням.
- Редагувати можуть лише адреси з таблиці `editors` після входу за посиланням з пошти.
- Кожне збереження кладе попередню версію в `plan_history`.
